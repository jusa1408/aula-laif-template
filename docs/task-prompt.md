A. Setup check (every run)
1. Call aula_discover once. Compare its children (id, name, institution code) with profile.kids.
   - A child in Aula but not in the profile: add {name: first name, fullName, id, institution, institutionName} to profile.kids, guess "type" from the institution/group name (vuggestue → nursery, børnehave → kindergarten, skole → school, SFO/fritidshjem/klub → sfo) and set "typeGuessed": true. Write the profile back ("set" with if_version).
   - A child in the profile but no longer in Aula: leave it, and add a line to the run report (step E).
   - Use child ids from the profile for every tool call. Institution codes of the family = the profile's kids' institutions; ignore everything from other codes.
2. School children (type "school" or "sfo"): use discover's capabilities (ugeplan, opgaver, ugebrev, lektier, huskelisten). Call only capabilities[area].tools[0]; skip an area whose notes say the widget is not detected unless profile kid.school.platforms lists it. Remember what returned data in kid.school.platforms (write the profile back when it changes).

B. Read Aula
3. aula_messages_list_threads (page 0, and page 1 if threads from the last 60 days continue). Open every thread with a latestMessage in the last 60 days with aula_messages_get_thread.
4. aula_posts_list with limit 40 (omit profileIds) and aula_notifications_list. Read every post from the last 60 days; an older post still counts if it announces a future event, deadline or recurring routine.
5. Attachments (Word, PDF, images): download with aula_posts_get_attachment (pass url exactly as listed) or aula_messages_get_attachment; files land in /private/tmp/aula-attachments on the computer. PDFs: aula_utils_extract_pdf_text. .docx and images: copy into the cloud workspace with mcp__remote-devices__device_stage_files (/private/tmp/aula-attachments/<name>); .docx → Python zipfile, word/document.xml, </w:p> → newline, </w:tc> → " | ", strip tags; images → open with Read. If unreadable, say "details in the attachment".
6. Attribute every item to a child: thread/post regardingChildren first, then the child's institution, then kid.hints.rooms and kid.hints.staff, then the author. Items for every child = "All". Several but not all = their first names joined with " & " (e.g. "Paula & Viggo"). Only ever use first names from the profile ("name", not "displayName"), "All", or such a list. This applies to EVERY list item that names a child, including fyi. Follow kid.hints.notes. Skip anything matching profile.ignore. Check that every child has been looked for — say in the report if a child had no items at all.

C. Build the data
7. Trips/groups: for each child with "trips", read the plan (kid.trips.source tells where: a thread id/subject, a post title or a document). Build trips = [{"date": "YYYY-MM-DD", "child": "<first name>", "text": "<English>", "text_da": "<Danish>", "lunch": true if packed lunch, "off": true if no trip that day, "source": "...", "source_da": "..."}] from today onward. "text" is only the trip itself (e.g. "Trip to the library"); a change or a move goes in "detail"/"detail_da". A newer plan or message replaces older ones. If no new plan can be read, keep the previous trips (from the output doc's "trips", or its older "storegruppe" field). When you find a plan for the first time, store where in kid.trips.source.
8. Lunch menus: for each child with "lunchMenu": look where kid.menuHint says first; if nothing is there (or no hint), search posts, messages and attachments (PDF, Word, images) from that child's institution for "madplan", "menu", "frokost", "ugens mad", "kostplan". When found, store where in kid.menuHint (title pattern, author, format, and the room/department it is for) and write the profile back.
   - Week: the page shows ONE week. Include every weekday (Mon–Fri, also past days) of the current week only. On Saturday/Sunday use the coming Monday's week as soon as its menu is in Aula; until then keep the week just gone. Drop days from earlier weeks.
   - Format {"note", "note_da", "days": [{"date", "lunch": [English], "lunch_da": [Danish as written], "snack": [...], "snack_da": [...], "note"?, "note_da"?}]}.
   - Shared or separate: children share a menu only when it is the very same plan (same post/document). A nursery and a kindergarten in the same institution often have separate plans – check the plan's title, room or department and kid.menuHint. If every lunch child is on the same plan, write it as "menu"; otherwise write "menus": {"<first name>": {...}} with one entry per lunch child (children on the same plan get the same content).

Calendar: aula_calendar_events for all children (profileIds = child ids) with start = the first day of the current month and end = the last day of the month five months ahead (Aula's timestamp format). (last day of a multi-day event), "start"? 11. Drop-off/pick-up plan: aula_presence_templates with all child ids for this week's Monday–Friday AND next week's Monday–Friday (two calls; Mon–Sun returns 403).
